## Patch logs are view deltas

A patch log records relative changes so a caller can update a materialized view.
It is not the source of truth. The document's changes and op set are the source
of truth; patches are the caller-facing explanation of what moved.

<SourceCard path="rust/automerge/src/patches/patch_log.rs">
Read `PatchLog`, `Event`, `migrate_actors`, `branch`, and `merge`. The actor
table migration is the part that matters for the desktop panic class.
</SourceCard>

## Why mismatch is recoverable

Patch logs contain actor-indexed data. If a patch log created for one document
actor table is reused with another document actor table, the indexes can stop
meaning what the caller thinks they mean. The fork patch set turns several
former unwraps into `AutomergeError::PatchLogMismatch`.

That error is different from invalid incoming change data. It can describe local
view/update machinery becoming stale, so rebuilding the local projection and
resetting peer sync state can be a meaningful recovery attempt.

<Callout title="Recoverable is intentionally narrow" tone="proof">
`PatchLogMismatch` is the main error that desktop should treat as rebuildable.
Errors like `InvalidObjId`, `InvalidSeqKey`, or `InvalidOpCounter` are evidence
about malformed or causally incomplete input, not a generic retry condition.
</Callout>

## Transaction constructor fixes

The `desktop-patches` stack makes AutoCommit transaction setup fallible instead
of unwrapping actor migration failures. It also adds `try_commit` and
`try_commit_with` so callers that care can observe setup errors directly.

The legacy `commit` and `commit_with` API shape remains compatibility-oriented:
it returns `None` on setup failure rather than exposing a new error type.
