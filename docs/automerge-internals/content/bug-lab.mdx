## What the bug lab is for

This page is a study guide for the `desktop-patches` fork stack, not a claim
that every patch is upstream-final. Each row answers: what was the panic or bad
acceptance shape, where should you read it, and what policy should desktop infer
from the returned error?

<Callout title="Provisional patch stance" tone="warning">
Treat these as reduced evidence. A patch graduates only when the reduction and
fix hold up against Automerge itself or are replaced by a better upstream
solution.
</Callout>

## How to add the next reduction

1. Start from the exact panic text or bad acceptance symptom.
2. Build the smallest Automerge-only test.
3. Assert both "no panic" and "no partial mutation" when mutation was possible.
4. Patch the earliest validation boundary.
5. Decide whether the resulting error is recoverable local skew or invalid data.
